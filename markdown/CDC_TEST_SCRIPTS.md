# CDC GC 测试脚本说明

## 文件清单

### 1. `test_cdc_gc.sh` - 完整测试脚本
主要的测试脚本，包含7个复杂的测试场景，用于全面验证CDC GC功能。

**功能**:
- 基本CDC保护测试
- 最小watermark策略测试
- 多数据库CDC保护测试
- 数据边界测试（应该被GC的数据）
- 空watermark测试
- watermark更新测试
- 并发多表CDC保护测试

**使用方法**:
```bash
# 基本用法
./test_cdc_gc.sh

# 自定义连接参数
export DB_HOST=127.0.0.1
export DB_PORT=6001
export DB_USER=dump
export DB_PASS=111
export ACCOUNT_ID=0
./test_cdc_gc.sh
```

### 2. `test_cdc_gc_quick.sh` - 快速验证脚本
用于快速验证CDC功能是否正常工作的脚本。

**功能**:
- 测试数据库连接
- 检查CDC表是否存在
- 查看当前CDC记录
- 检查GC、checkpoint、flush配置

**使用方法**:
```bash
./test_cdc_gc_quick.sh
```

### 3. `test_cdc_gc_README.md` - 详细使用说明
包含详细的使用说明、配置建议、故障排查等信息。

## 测试场景说明

### 场景1: 基本CDC保护测试
- **目的**: 验证基本的CDC数据保护功能
- **验证点**: 设置了watermark后，数据不会被GC删除

### 场景2: 最小watermark策略
- **目的**: 验证同一数据库多个表的watermark取最小值策略
- **验证点**: 数据库级别的保护机制正确工作

### 场景3: 多数据库CDC保护
- **目的**: 验证多个数据库的独立CDC保护
- **验证点**: 只有设置了CDC的数据库被保护

### 场景4: 数据边界测试
- **目的**: 验证watermark边界条件
- **验证点**: 旧数据可以被GC，新数据被保护

### 场景5: 空watermark测试
- **目的**: 验证空watermark表示保护所有数据
- **验证点**: 边界情况处理正确

### 场景6: watermark更新测试
- **目的**: 验证watermark更新后的保护行为
- **验证点**: 动态更新机制正确工作

### 场景7: 并发多表CDC保护
- **目的**: 验证多个表同时设置CDC保护
- **验证点**: 并发场景下的正确性

1. 检查日志输出
2. 验证配置是否正确
3. 查看故障排查部分

## 故障排查

### 问题1: 连接失败
**错误**: `无法连接到数据库，请检查连接参数`

**解决方案**:
- 检查DB_HOST、DB_PORT是否正确
- 检查数据库服务是否运行
- 检查防火墙设置

### 问题2: 表不存在
**错误**: `mo_cdc_watermark表不存在`

**解决方案**:
- 确保CDC功能已启用
- 检查表是否已创建
- 验证数据库版本是否支持CDC

### 问题3: 数据被错误删除
**错误**: `测试失败: 数据被错误删除`

**解决方案**:
- 检查GC配置是否正确
- 检查watermark时间戳是否正确
- 检查checkpoint是否正常执行
- 增加等待时间

### 问题4: 测试超时
**解决方案**:
- 增加wait_for_checkpoint和wait_for_gc的等待时间
- 检查系统负载是否过高
- 调整GC和checkpoint间隔

## 注意事项

1. **时间同步**: 确保系统时间准确，watermark时间戳依赖系统时间
2. **数据隔离**: 测试脚本会创建和删除测试数据库，不会影响生产数据
3. **并发测试**: 如果同时运行多个测试实例，请使用不同的数据库名称
4. **资源占用**: 测试会创建多个数据库和表，注意资源使用情况
5. **客户端兼容**: 脚本支持mysql和mo客户端，会自动检测

## 扩展测试
