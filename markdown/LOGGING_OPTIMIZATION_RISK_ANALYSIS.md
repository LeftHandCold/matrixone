# 日志优化改动风险分析

## 改动概述

本次改动主要优化了 `pkg/common/morpc/backend.go` 中的错误日志记录，减少正常连接生命周期中的噪音日志。

### 主要改动

1. **readLoop 日志优化**：区分正常退出和异常退出
2. **错误日志过滤**：将预期错误降级为 DEBUG 级别
3. **移除 goetty session logger**：避免 goetty 库内部的噪音日志
4. **添加辅助函数**：`isExpectedReadError` 和 `isExpectedCloseError`

## 风险分析

### ✅ 低风险改动

#### 1. 日志级别降级
- **改动**：预期错误从 ERROR 降级为 DEBUG
- **影响**：不影响错误处理逻辑，只是日志级别变化
- **风险**：低
- **验证**：错误仍然会传递给 `scheduleResetConn(err)`，重连逻辑不受影响

#### 2. normalExit 标志
- **改动**：添加 `normalExit` 标志来区分正常退出和异常退出
- **影响**：只影响 "read loop stopped" 的日志级别
- **风险**：低
- **验证**：不影响错误处理流程，错误仍然会被正确处理

#### 3. 移除 goetty session logger
- **改动**：移除 `WithSessionLogger`，保留 `WithAppLogger`
- **影响**：goetty 库内部的 session 级别日志不再输出
- **风险**：低
- **验证**：应用级别的日志仍然保留，关键错误仍会记录

### ⚠️ 中等风险改动

#### 1. 错误过滤的字符串匹配
- **改动**：使用 `strings.Contains` 来匹配错误消息
- **潜在问题**：
  - 如果错误消息中包含 "EOF" 但不是真正的 EOF 错误，也会被过滤
  - 如果错误消息中包含 "illegal state" 但不是预期的状态错误，也会被过滤
- **风险**：中等
- **缓解措施**：
  - 当前过滤的错误都是常见的连接生命周期错误
  - 即使被误判，错误仍然会传递给重连逻辑
  - 可以通过 DEBUG 日志查看详细信息

#### 2. 错误过滤范围
- **过滤的错误类型**：
  - "use of closed network connection"
  - "illegal state"
  - "EOF"
  - `backendClosed`
- **潜在问题**：某些真正的错误可能包含这些字符串
- **风险**：中等
- **缓解措施**：
  - 这些错误都是连接关闭相关的，在正常生命周期中很常见
  - 真正的网络错误（如超时、连接拒绝）不会被过滤
  - 错误仍然会传递给重连逻辑

### 🔍 需要关注的点

#### 1. 错误处理流程验证
- **验证点**：确保即使错误被标记为预期错误，重连逻辑仍然正常工作
- **代码位置**：`readLoop` 第 610 行 `rb.scheduleResetConn(err)`
- **结论**：✅ 已验证，错误仍然会传递给重连逻辑

#### 2. 日志可观测性
- **关注点**：降级为 DEBUG 的错误是否会影响问题排查
- **缓解措施**：
  - 预期错误仍然会记录在 DEBUG 级别
  - 真正的异常错误仍然记录为 ERROR
  - 可以通过调整日志级别来查看详细信息

#### 3. 与其他模块的兼容性
- **检查点**：其他模块是否依赖这些 ERROR 日志
- **结论**：✅ 无影响，因为：
  - 这些是内部实现细节
  - 错误处理逻辑没有改变
  - 只是日志级别变化

## 总结

### 风险评估
- **整体风险**：**低到中等**
- **主要风险**：错误过滤可能误判某些错误
- **影响范围**：仅影响日志输出，不影响功能逻辑

### 建议
1. ✅ **可以合并**：改动风险可控，主要是日志优化
2. ⚠️ **需要监控**：部署后需要关注连接相关的指标
3. 📝 **文档更新**：建议更新日志相关的文档，说明预期错误的处理方式
