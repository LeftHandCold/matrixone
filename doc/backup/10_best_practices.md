# 最佳实践

## 1. 备份策略

### 1.1 备份频率建议

| 数据重要性 | 全量备份 | 增量备份 |
|-----------|---------|---------|
| 关键业务 | 每天 | 每小时 |
| 重要数据 | 每周 | 每天 |
| 一般数据 | 每月 | 每周 |

### 1.2 备份时间窗口

- 选择业务低峰期执行备份
- 避免与其他资源密集型任务冲突
- 预留足够的备份时间

### 1.3 备份保留策略

```
建议保留周期:
- 每日备份: 保留 7 天
- 每周备份: 保留 4 周
- 每月备份: 保留 12 个月
```

## 2. 存储选择

### 2.1 本地存储

优点:
- 备份速度快
- 无网络依赖
- 成本较低

缺点:
- 容灾能力弱
- 扩展性有限

适用场景:
- 开发测试环境
- 小规模部署

### 2.2 S3 对象存储

优点:
- 高可用性
- 无限扩展
- 异地容灾

缺点:
- 网络依赖
- 成本较高

适用场景:
- 生产环境
- 大规模数据
- 合规要求

### 2.3 配置示例

```sql
-- 本地备份
BACKUP DATABASE TO '/backup/mo_backup_20231201';

-- S3 备份
BACKUP DATABASE TO 's3://my-bucket/backup/20231201'
WITH endpoint='s3.amazonaws.com',
     region='us-east-1',
     access_key_id='AKIAXXXXXXXX',
     secret_access_key='xxxxxxxx';

-- MinIO 备份
BACKUP DATABASE TO 's3://backup-bucket/mo_backup'
WITH endpoint='minio.example.com:9000',
     access_key_id='minioadmin',
     secret_access_key='minioadmin',
     is_minio='true';
```

## 3. 性能优化

### 3.1 并行度设置

```sql
-- 根据 CPU 核心数设置并行度
BACKUP DATABASE TO '/backup/path' WITH parallelism='128';
```

建议值:
- 8 核以下: 50
- 8-16 核: 80
- 16-32 核: 128
- 32-64 核: 256
- 64 核以上: 512

### 3.2 网络优化

S3 备份时:
- 使用同区域的 S3 存储桶
- 配置合适的网络带宽
- 考虑使用 VPC 端点

### 3.3 存储优化

- 使用 SSD 存储
- 确保足够的 IOPS
- 避免存储瓶颈

## 4. 监控和告警

### 4.1 关键指标

- 备份持续时间
- 备份数据量
- 备份成功率
- 存储空间使用

### 4.2 告警设置

```
建议告警:
- 备份失败: 立即告警
- 备份超时: 超过预期时间 50% 告警
- 存储空间: 使用率超过 80% 告警
```

### 4.3 日志监控

关注以下日志:
```
GC-Backup-Protection-Set
GC-Backup-Protection-Updated
GC-Backup-Protection-Removed
backup: copy file
backup: end backup
```

## 5. 安全建议

### 5.1 访问控制

- 限制备份目录访问权限
- 使用专用的 S3 访问密钥
- 定期轮换密钥

### 5.2 数据加密

- 启用 S3 服务端加密
- 考虑传输加密 (HTTPS)
- 保护备份元数据

### 5.3 审计日志

- 记录所有备份操作
- 监控异常访问
- 定期审查日志

## 6. 灾难恢复

### 6.1 恢复演练

- 定期进行恢复演练
- 验证备份可用性
- 记录恢复时间

### 6.2 异地备份

```
建议架构:
主站点 ──备份──▶ 本地存储
         │
         └──复制──▶ 异地 S3
```

### 6.3 RTO/RPO 规划

| 级别 | RPO | RTO |
|-----|-----|-----|
| 关键 | < 1 小时 | < 4 小时 |
| 重要 | < 24 小时 | < 24 小时 |
| 一般 | < 7 天 | < 72 小时 |

## 7. 常见问题

### 7.1 备份失败

检查项:
1. 存储空间是否充足
2. 网络连接是否正常
3. 权限是否正确
4. GC 是否正在运行

### 7.2 备份过慢

优化方向:
1. 增加并行度
2. 检查网络带宽
3. 优化存储性能
4. 选择合适的备份时间

### 7.3 恢复失败

检查项:
1. 备份文件完整性
2. 版本兼容性
3. 目标环境配置
4. 存储空间
